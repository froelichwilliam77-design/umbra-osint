# Umbra target schema

Umbra loads four schema layers:

1. **`wmn-data.json`** — WhatsMyName registry. Sync with `npm run sync:wmn`.
2. **`sherlock-overlay.json`** — Sherlock platforms not already in WMN, converted to dual-condition records. Regenerated by the same sync script.
3. **`sites.curated.yaml`** — extra handle targets, extractors, and overrides (wins on name collision).
4. **`oracles.yaml`** — silent email registration oracles (no SMTP, no password-reset mail). v1.2.0 shipped 53; current registry is **161** Holehe-style signup / login-precheck / public-API checks. Chronically CSRF-dead modules are `quarantine:`'d and emitted as **blocked** without a probe.

Handle sites: **1001** unique (717 WMN + 267 Sherlock overlay + 40 curated; 961 clearnet / 40 NSFW).

## Handle site (WhatsMyName-compatible)

```json
{
  "name": "GitHub (User)",
  "uri_check": "https://api.github.com/users/{account}",
  "uri_pretty": "https://github.com/{account}",
  "e_code": 200,
  "e_string": "\"login\":",
  "m_code": 404,
  "m_string": "Not Found",
  "cat": "coding",
  "known": ["octocat"],
  "protection": ["cloudflare"]
}
```

Classification is **dual-condition**:

- **found** if `status == e_code` AND `e_string` is in the body (empty string = ignore that half).
- **miss** if `status == m_code` AND `m_string` is in the body.
- Both true with a substring collision (`"them":` vs `"them":null`) → the **more specific** string wins.
- Both true otherwise, or neither → **escalate** (last resort).
- `401` / `403` / `429` / `451` / CAPTCHA / WAF signatures → **blocked**, never a miss.
- HTTP `404` / `410` / `400` without an exist match → **miss** (status indicates absence even if `m_string` drifted).
- Redirects to login / explore / generic home → **miss** with a reason.
- JSON bodies that name `{account}` recover stale exist strings as **found**.

Sherlock `status_code` sites map to `e_code=200` / `m_code=<errorCode>`. Sherlock `message` sites map to `m_string=<errorMsg>` (longest message if the source lists several). `403`/`429`/CAPTCHA still classify as **blocked**.

`{account}` is replaced with the handle. Optional `{account}` also works in `post_body` and header values.

## Curated overlay

```yaml
sites:
  - name: Example
    uri_check: https://example.com/{account}
    e_code: 200
    e_string: "profile"
    m_code: 404
    m_string: "not found"
    cat: social
extractors:
  - site: GitHub (User)
    kind: json
    avatar: avatar_url
    bio: bio
    followers: followers
    displayName: name
```

## Email oracles

Oracles must be silent: they read public signup / login / profile endpoints only. Umbra will not call password-reset endpoints that email the subject. The HIBP oracle is omitted entirely unless `HIBP_API_KEY` is set.
